# Primary Wallpaper Agent v0.5.2 Preview

Switching the Windows primary display and temporary wallpaper/display failures no longer leave the watcher permanently paused. The watcher waits for complete, settled display observations, restores the saved primary/secondary roles and retries recoverable failures automatically while retaining diagnostic logs.

- A stable new picture set through Windows on the current primary is imported as the **primary role's new picture**. A verified cached copy follows that role on later primary changes. Equal-byte paths do not create repeated imports; changed image bytes at the same external path are observed.
- Secondary pictures are set in this app only. Windows changes on secondaries are replaced with the app's shared secondary image or black. Windows set-for-all imports the primary picture and restores the app's choice on every secondary.
- During an observed display transition, saved role images take priority until their assignments settle. The watcher does not mistake that transition for a new primary choice. A pre-first-poll primary matching the saved secondary is also rebased to the saved primary.
- Mapping, setter and readback failures retry with backoff capped at 30 seconds. Eight successful repairs in a rolling minute cause a temporary cooldown, followed by automatic retry. Unsupported Windows modes are preserved while waiting for Picture/Fill; no mode is forced.
- Manual Pause stays paused until Resume, retaining the prior display baseline. New transition, candidate, retry and recovery events use the existing bounded logs and diagnostics export. Imports preserve secondary selection, preferences and startup registration; primary Undo remains available.

## Verification and known limits

- Build: zero warnings/errors. Automated run: **19/20 suites passed**, including wallpaper policy, primary/secondary changes, hotplug, recovery, settings/Undo, diagnostics, updates and native window visibility.
- The remaining DPI test fails at `User can shrink the window vertically` during the simulated 150% layout check. Exporting and building the unchanged prior commit reproduces the identical failure and layout dimensions. This existing failure is disclosed and remains outside this wallpaper patch.
- The recovery tests use generated images, fake desktop/startup backends and a deterministic clock. They cover delayed remembered images on a primary-only switch, Windows primary/all-display/secondary changes, missing source files, same-path changes, aliases, repeated failures/cooldown, manual Pause/Resume and transactional rollback. They do not establish physical-monitor, Remote or Virtual Desktop results.
- Windows state observations do not authenticate who changed a picture. A picture change concurrent with an observed display transition is treated as transition recovery. The app keeps one primary and one shared secondary image across Virtual Desktops; separate per-desktop pictures are not maintained. See [behavior and verification](https://github.com/thep497/PrimaryWallpaperAgent/blob/main/docs/testing/AUTO-RECOVERY-TEST.md).

## Packages and update

Full includes .NET 10 Windows Desktop Runtime; Slim requires a compatible installed .NET 10 Windows Desktop Runtime x64. Both are single-file Windows x64 apps. Enable **Include preview releases** in About to receive this preview. Full stays Full; Slim stays Slim. Exit an older running instance before manually replacing or launching the EXE.

The release includes the signed update manifest, its signature and SHA256SUMS.txt. Windows publisher signing remains unchanged; follow the existing [download and checksum instructions](https://github.com/thep497/PrimaryWallpaperAgent#download-warning-and-sha-256).
