# Primary Wallpaper Agent v0.3.1 Preview

Three usability and maintenance improvements for the single-file Windows x64 app.

## Changes

- Launching the EXE again opens Settings in the existing v0.3.1 instance. A minimized Settings window is restored; a closed one is reopened.
- A duplicate --startup launch exits quietly without opening Settings or creating a second agent.
- About is available through the version link in the Settings header, with the actual running version, GitHub Releases and the current data folder. Thai and English are supported.
- Managed logs and diagnostic snapshots are retained for 30 days, with a target combined limit of 50 MiB. Text logs rotate at 2 MiB with one previous file.
- Cleanup preserves the current active log/session, settings, wallpaper assets, unknown files and nested/reparse directories. Locked files are skipped and retried on later cleanup.

## Update from v0.3.0

Exit the old tray instance once before opening v0.3.1. The older version does not support the new activation protocol. Replace the EXE at the same location to preserve the startup path. New per-user data remains separate; older adjacent settings/assets remain in legacy folder mode.

Download PrimaryWallpaperAgent.exe. It includes .NET 10 and needs no separate .NET runtime installation. SHA256SUMS.txt is supplied for verification.

## Validation and limits

All 11 automated suites pass, including cross-process activation, log retention and About. Additional junction testing confirms cleanup does not follow the link target. Thai/English UI screenshots were inspected. The renamed packaged EXE is checked with isolated fresh data and shared .NET lookup disabled.

Tests use fake wallpaper/startup backends and generated image fixtures. Existing wallpaper behavior is unchanged. The user reported normal launch and expected wallpaper behavior on 20 October; detailed projector, >3 physical displays, DPI transition and logon-startup coverage remains pending.

This remains a prerelease and the binary is unsigned. Spotlight/slideshow and separate images per Virtual Desktop remain unsupported. Automatic updating is planned separately; it is not included in v0.3.1.
